# 音频识别与失败诊断（0.2.2）

“未识别到有效音频头”不是文件损坏的定论。旧版提示把解码算法不匹配、内部音频编码未集成、数据不完整和识别器误判混在了一起。没有具体样本或诊断，不能据此断言是哪一种。

## 本次修正

- 在有边界校验的前提下跳过前置 ID3v2 标签，再检测 AAC、FLAC 和 MP3；处理连续标签和 ID3v2.4 footer。原数据包括标签逐字节保留，不重新编码。
- 对已验证为普通音频、却仍使用 NCM／旧 QMC／KWM／XM／TM 后缀的文件，不再重复解码。只接受结构边界处的有效音频，不能因为密文中偶然出现同步字就原样导出。
- ADTS AAC 和 MPEG 音频使用连续有界帧校验。损坏或未知输出仍失败，不会生成假 MP3。
- 在 Blob Worker 和主线程兼容模式之间保留结构化错误。失败条目旁的问号按钮为“查看诊断”，可打开诊断窗口并保存 JSON。

## 如何反馈

重新选择原始文件处理。如果仍失败，点击失败条目旁的“查看诊断”→“保存诊断 JSON”。可分享 `unlock-music-diagnostic.json` 或诊断窗口内容。

单文件诊断只包含版本、文件后缀、输入/输出字节数、粗粒度容器标签、实际解码器、阶段、错误代码及标签偏移；不包含文件名、歌曲标签、音频字节、十六进制转储、密钥或路径，也不会自动上传。

“导出记录”是另一种完整会话报告，仍包含文件名和歌曲元数据。需要保护这些信息时请分享单文件诊断，不要分享整个会话报告。

| 字段/代码 | 含义 |
|---|---|
| `decoder: qmc-legacy` | 使用了静态掩码的旧 QMC 算法；并不证明文件属于该版本 |
| `stage: audio-header` | 已读取文件并得到候选输出，但尚未确认音频类型 |
| `AUDIO_HEADER_UNRECOGNIZED` | 目前无法区分不支持的加密、内部编码不支持与数据不完整 |
| `TRUNCATED_ID3_TAG` | 声明的标签长度超过可读取数据 |
| `DECODE_FAILED` | 格式解析或解密步骤失败，结合界面错误进一步排查 |
| `AUDIO_VALIDATION_FAILED` | 候选音频的容器结构校验没有通过 |
| `UNSUPPORTED_FORMAT` | 当前未集成该格式 |
